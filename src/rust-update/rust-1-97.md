# Rust 1.97.0 มาแล้ว

> 📅 วันที่เผยแพร่: 2026-07-11

คุ้นๆ ว่าช่วงเดือนพฤษภาคมที่ผ่านมาเพิ่งเขียนอัปเดตจาก Rust 1.96.0 ไป Rust 1.97.0 มาแล้ว โดยไฮไลต์สำคัญของรอบนี้คือการเปิดใช้งานระบบ Symbol Mangling แบบ v0 เป็นค่าเริ่มต้น (Default) หลังจากที่รองรับมานานตั้งแต่ Rust 1.59 แต่ต้องเปิดใช้งานเองผ่านแฟล็กคอมไพเลอร์จนได้เวลาเก็บเข้าค่าเริ่มต้นเสียที

ปกติแล้วรูปแบบเดิมจะอ้างอิง Itanium ABI ซึ่งไม่ค่อยเข้าทางกับความสามารถหลายอย่างของ #Rust โดยเฉพาะเรื่องชื่อสัญลักษณ์ (Symbol) ที่ตอนนี้ v0 จะเก็บข้อมูลของ Generic Parameter ไว้อย่างครบถ้วน แทนที่จะซ่อนอยู่หลังค่าแฮชเหมือนในอดีต สิ่งนี้ส่งผลให้การดีบัก การทำ Profiling และการวิเคราะห์ไบนารีทำได้ง่ายขึ้นเป็นกอง อีกทั้งยังเป็นก้าวสำคัญก่อนที่ระบบ Symbol Mangling แบบเดิมจะถูกถอดออกไปในอนาคต

อีกการเปลี่ยนแปลงที่น่าสนใจคือ Cargo สามารถจัดการระดับของ Warning ได้โดยตรง จากเดิมที่หลายโปรเจกต์นิยมใช้ `RUSTFLAGS=-Dwarnings` เพื่อให้ CI ล้มทันทีเมื่อเจอคำเตือน แนวทางดังกล่าวมีข้อเสียตรงที่ทำให้ Build Cache ใช้งานต่อไม่ได้ (เพราะแฟล็กไปกระทบ fingerprint ของการคอมไพล์) ใน Rust 1.97 เราสามารถกำหนด `CARGO_BUILD_WARNINGS=deny` เพื่อให้ Cargo จัดการเรื่องนี้แทนได้ โดยไม่กระทบ Cache เดิม นอกจากนี้ยังเอาไปใช้ร่วมกับ `--keep-going` เพื่อรวบรวมข้อผิดพลาดทั้งหมดในรอบเดียว หรือสลับเป็น `allow` ชั่วคราวระหว่างแก้ไขโค้ดบนเครื่องพัฒนาได้สะดวกกว่าเดิมมาก

ด้านกระบวนการลิงก์ (Linking) ก็มีการปรับพฤติกรรมเช่นกัน ก่อนหน้านี้หากการลิงก์สำเร็จ `rustc` จะซ่อนข้อความจาก Linker ไว้ทั้งหมด แต่ในหลายกรณี ข้อความเหล่านั้นอาจเป็นสัญญาณเตือนของปัญหาที่ควรได้รับการแก้ไข Rust 1.97 จึงเปลี่ยนมาแสดงข้อความเหล่านี้เป็น Warning Lint (`linker_messages`) โดยค่าเริ่มต้น พร้อมทั้งกรองข้อความที่เป็น False Positive หรือเป็นพฤติกรรมปกติของระบบออกไปบางส่วนแล้ว หากยังมีข้อความที่ไม่ต้องการ ก็สามารถกำหนดระดับของ Lint นี้ใน `Cargo.toml` ให้เป็น `allow` ได้เช่นกัน

สำหรับ Standard Library ก็มี API หลายตัวที่ถูกประกาศเป็น Stable ไม่ว่าจะเป็นการเพิ่ม `Default` ให้กับ `RepeatN` ทำให้ `ffi::FromBytesUntilNulError` รองรับ `Copy` ได้ รวมถึงกลุ่ม API ด้านการจัดการบิตของชนิดข้อมูลจำนวนเต็มและตระกูล `NonZero` อย่าง `isolate_highest_one`, `highest_one` และ `bit_width` ที่พร้อมใช้งานบน Stable แล้ว นอกจากนี้ `char::is_control` ยังสามารถเรียกใช้ใน Const Context ได้ ทำให้การคำนวณบางอย่างย้ายไปเกิดขึ้นตั้งแต่ช่วง Compile Time ได้สะดวกยิ่งขึ้น

ใครที่ติดตั้ง #Rust ผ่าน `rustup` อยู่แล้ว สามารถอัปเดตได้ทันทีด้วยคำสั่ง `rustup update stable` เพื่อทดลองความสามารถใหม่เหล่านี้ได้ครับ
