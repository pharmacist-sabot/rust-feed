# Astro 7.0 เมื่อเว็บเฟรมเวิร์กย้ายแกนหลักออกจาก JavaScript

> 📅 วันที่เผยแพร่: 2026-06-26

เอาจริง ๆ Astro 6.0 เพิ่ง release ไปเมื่อ 10 มีนาคม 2569 ที่ผ่านมานี่เอง โปรเจกต์เว็บบล็อกของผมที่เดิมใช้ Astro 5 เพิ่งอัพเป็น 6 ได้ไม่นาน Astro 7 ก็มาอีกแล้ว (ตามไม่ทันละคร้าบ 😅) เรื่องของเรื่องคือไฟล์บล็อก mdx เปิดอ่านไม่ได้ เพิ่งจะมาดูเมื่อกี้นี่แหละครับ โอโห้ มีหัวข้อในการอัพเดตคือ Markdown & MDX in Rust งานเข้า 555 งั้นมาดูกันดีกว่าครับว่า Astro 7.0 เอา #Rust มาใช้ตรงไหนบ้าง

การเปลี่ยนผ่านสถาปัตยกรรมของ Astro 7.0 สู่การเป็น Rust-based toolchain แบบเต็มตัว ผมมองว่าวงการเว็บทูลลิ่ง (Web tooling) ต้องการก้าวข้ามขีดจำกัดด้านประสิทธิภาพของ JavaScript และ Node.js โดยในเวอร์ชันนี้ ตัวคอมไพเลอร์ฟอร์แมต `.astro` ได้ถูกเขียนขึ้นใหม่ทั้งหมดด้วยภาษา #Rust จากเดิมที่เป็น Go พร้อมกับปรับปรุงไปป์ไลน์การประมวลผล Markdown และ MDX ให้ทำงานบนเนทีฟไบนารี (Native binary) ร่วมกับการมี WebAssembly (WASM) เป็นระบบสำรองสำหรับสภาพแวดล้อมที่จำเป็น ช่วยแก้ปัญหาคอขวดด้าน CPU-bound ในการคอมไพล์โปรเจกต์ขนาดใหญ่

ตัวคอมไพเลอร์ `.astro` ตัวใหม่ ระบบเบื้องหลังเลือกใช้ `oxc` สำหรับขั้นตอนการทำ Parsing และใช้ Lightning CSS ในการจัดการ CSS Scoping ซึ่งนอกจากจะช่วยลด Overhead ในการทำงานเมื่อเทียบกับคอมไพเลอร์ตัวเดิมแล้ว การเขียนขึ้นใหม่ด้วย #Rust ยังเปิดโอกาสให้ทีมพัฒนาปรับปรุงความเข้มงวดของระบบ JSX-style strictness และการจัดการ Whitespace ให้ตรงตามสเปกมาตรฐานได้โดยไม่ต้องแลกกับประสิทธิภาพที่สูญเสียไป แม้ว่าผลทดสอบการคอมไพล์ `.astro` แบบแยกเดี่ยวจะเร็วขึ้นราว 6% แต่เมื่อโครงสร้างพื้นฐานนี้ทำงานร่วมกับระบบอื่นใน Pipeline ก็นำไปสู่การประมวลผลโดยรวมที่เสถียรและเร็วขึ้น

จุดเปลี่ยนสำคัญอีกด้านคือ Satteri ซึ่งเป็นตัวประมวลผล Markdown และ MDX ตัวใหม่ที่เขียนด้วย #Rust เพื่อเข้ามาแทนที่ระบบเดิมอย่าง unified (remark และ rehype) ที่ทำงานบน JavaScript คอขวดเดิมของระบบเก่าคือการต้องแปลงไฟล์เป็น AST (Abstract Syntax Tree) แล้วให้ปลั๊กอินแต่ละตัวเดินไล่ตรวจทั้งทรี (Tree traversal) ซ้ำไปซ้ำมา แต่ Satteri ซึ่งมีสถาปัตยกรรมภายในเป็น #Rust โดยใช้ `pulldown-cmark` และ `oxc` ได้เปลี่ยนแนวคิดใหม่ด้วยการออกแบบ Plugin API ให้ปลั๊กอินประกาศเฉพาะประเภทโหนด (Node types) ที่สนใจล่วงหน้า แล้วข้ามโหนดที่เหลือได้ทันที ประกอบกับการรันบนระบบเนทีฟ ทำให้ลดเวลาในการบิลด์หน้าเอกสารที่มีเนื้อหาหนาแน่นลงไปได้นับนาที

นอกจากนี้ Astro 7 ยังได้อัปเกรดไปใช้ Vite 8 ซึ่งมาพร้อมกับ Rolldown ตัว Bundler ตัวใหม่ที่เขียนด้วย #Rust เพื่อมาแทนที่ esbuild และ Rollup โดยตรง ซึ่งในแง่ประสิทธิภาพ Rolldown สามารถทำความเร็วในเบนช์มาร์กได้เหนือกว่า Rollup ถึง 10–30 เท่า เมื่อนำจิ๊กซอว์ฝั่ง #Rust ทั้งหมดมารวมกัน ทั้งคอมไพเลอร์ Satteri และ Rolldown ส่งผลให้ระยะเวลาในการบิลด์โดยรวมของโปรเจกต์จริงลดลงไปถึง 15–61% ถือเป็นกรณีศึกษาที่แสดงให้เห็นถึงการนำคุณสมบัติเด่นของ #Rust ทั้งเรื่อง Zero-cost abstractions และความเร็วในการประมวลผลระดับเนทีฟมาใช้แก้ปัญหาคอขวดของระบบเว็บแอปพลิเคชันได้อย่างมีประสิทธิภาพ
