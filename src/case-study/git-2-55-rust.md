# ย้ายระบบ C ขนาดใหญ่ไป Rust อย่างไรไม่ให้พัง? เชิญชวนดูกรณีศึกษา Git v2.55

> 📅 วันที่เผยแพร่: 2026-07-02

การเดินทางของภาษา #Rust ในโค้ดเบสของ Git ได้ก้าวมาถึงจุดเปลี่ยนสำคัญในเวอร์ชัน v2.55 ที่เปลี่ยนสถานะจากการทดลองเปิดใช้งานมาเป็นข้อกำหนดเริ่มต้น (Required by default) ในระบบคอมไพล์หลักทั้ง Make และ Meson ซึ่งหากผู้ที่บิลด์ซอร์สโค้ดไม่ต้องการใช้งาน จะต้องสั่งปิดเองผ่านคอมมานด์ไลน์ด้วยคำสั่งอย่าง `-Drust=disabled` ใน Meson หรือ `NO_RUST=YesPlease` ใน Makefile การปรับเปลี่ยนนี้ไม่ได้เกิดขึ้นอย่างกะทันหัน แต่เป็นผลลัพธ์ของกระบวนการวางรากฐานและทยอยผสานระบบอย่างเป็นขั้นเป็นตอนร่วมกับนักพัฒนาในคอมมูนิตี้มาหลายเวอร์ชัน

หากย้อนมองเส้นทางวิวัฒนาการนี้ จะพบว่า Git เริ่มเปิดรับ #Rust ครั้งแรกเมื่อมีนาคม 2025 ในเวอร์ชัน 2.49 โดยเริ่มจากการเขียน bindings เพื่อให้โค้ด #Rust สามารถเรียกใช้งานฟังก์ชันภายในของ libgit ได้ก่อน โดยที่ยังไม่มีการนำโค้ด #Rust ไปใช้งานจริงในไบนารีหลัก จากนั้นในเวอร์ชัน 2.52 (พฤศจิกายน 2025) จึงได้เริ่มส่งโค้ดใช้งานจริง (Production code) ชุดแรกเข้าสู่ระบบในส่วนของระบบย่อย varint ซึ่งในขณะนั้นถูกออกแบบให้เป็นบอลลูนทดสอบ (Test balloon) ที่คอมไพล์แบบทางเลือกและมีโค้ดภาษา C สำรองไว้ เพื่อให้ผู้จัดทำแพ็กเกจ (Distributors) ได้มีเวลาปรับตัวและเตรียมความพร้อมของเครื่องมือบิลด์

ความก้าวหน้าเชิงโครงสร้างที่สำคัญเกิดขึ้นในเวอร์ชัน 2.54 ช่วงต้นปีนี้ เมื่อมีการนำ #Rust เข้ามาจัดการกับชนิดข้อมูลระดับล่างอย่าง ObjectID ซึ่งเป็นส่วนหนึ่งของความพยายามในการทำงานร่วมกันระหว่างแฮชแบบ SHA-1 และ SHA-256 การเลือกใช้ #Rust กับโครงสร้างข้อมูลหลักนี้สะท้อนให้เห็นถึงการนำภาษาใหม่เข้ามาช่วยดูแลระบบที่มีความซับซ้อนสูงและต้องการความถูกต้องของข้อมูลเป็นอันดับแรก ก่อนที่จะขยับมาเตรียมความพร้อมในส่วนของโมดูลคำนวณความต่างอย่าง `xdiff/` ในเวอร์ชัน v2.55 ล่าสุดนี้

ความสำเร็จในการเปลี่ยนผ่านเทคโนโลยีทีละส่วนของโครงการขนาดใหญ่นี้ เกิดขึ้นจากความร่วมมืออย่างต่อเนื่องภายในคอมมูนิตี้ โดยมีนักพัฒนาหลักอย่าง brian m. carlson, Patrick Steinhardt, Ezekiel Newren และ Calvin Wan ร่วมผลักดัน ซึ่งแนวทางการออกแบบระบบบิลด์ให้มีทางเลือกสำรองและค่อย ๆ เพิ่มความเข้มงวดในการกำหนด dependency นี้ ถือเป็นกรณีศึกษาที่ดีอย่างยิ่งสำหรับการนำภาษา #Rust เข้าไปปรับปรุงระบบสืบทอด (Legacy system) ขนาดใหญ่ในระดับอุตสาหกรรม แน่นอนว่าคนเห็นต่างย่อมมีเป็นธรรมดา
