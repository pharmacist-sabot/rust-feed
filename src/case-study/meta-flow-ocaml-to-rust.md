# เมื่อ Meta ย้าย Flow จาก OCaml ไป #Rust

> 📅 วันที่เผยแพร่: 2026-07-04

เปิดคลิปมาด้วย Atwood's Law ที่ว่า "แอปพลิเคชันใด ๆ ก็ตามที่สามารถเขียนด้วยภาษา JavaScript ได้ ในท้ายที่สุดแล้วมันก็จะถูกเขียนด้วยภาษา JavaScript" 😉 แต่หารู้ไม่ว่า ตอนนี้แอปพลิเคชันใด ๆ ก็ตามที่เขียนด้วย JavaScript แต่เครื่องมือ JavaScript ทั้งหมดจะถูกเขียนด้วย #Rust ในท้ายที่สุด 😅

กลับมาที่เนื้อหาหลักของคลิปกันครับ การที่ทีม Flow ของ Meta ตัดสินใจย้ายระบบ Static Type Checker จาก OCaml มาเป็น #Rust ถือเป็นกรณีศึกษาที่น่าสนใจสำหรับคนทำเครื่องมือพัฒนา เพราะเดิมที OCaml ก็เป็นภาษาที่ได้รับการยอมรับมานานว่าถนัดงานประเภท Compiler, Parser และการจัดการ Abstract Syntax Tree (AST) อยู่แล้ว แต่เมื่อโค้ดเบสของ Meta เติบโตขึ้นเรื่อย ๆ โดยเฉพาะในโมโนรีโปขนาดใหญ่ ข้อจำกัดด้านการขยายระบบและการทำงานร่วมกับ Ecosystem ของ JavaScript ก็เริ่มชัดเจนขึ้น

จริง ๆ แล้วทีม Flow เคยประเมินการพอร์ตมายัง #Rust ตั้งแต่ปี 2019 แต่ในเวลานั้นความเสี่ยงยังสูงเกินไป จนกระทั่งช่วงไม่กี่ปีที่ผ่านมาเริ่มมีตัวอย่างความสำเร็จให้เห็นมากขึ้น ไม่ว่าจะเป็นการพอร์ต Pyre ของ Meta ไปเป็น Pyrefly ที่เขียนด้วย #Rust ซึ่งทำงานเร็วขึ้นหลายเท่าตัว หรือการที่ Microsoft ประกาศย้าย TypeScript Compiler ไปยัง Go พร้อมอ้างว่าประสิทธิภาพเพิ่มขึ้นอย่างมาก เหตุการณ์เหล่านี้สะท้อนแนวโน้มเดียวกันว่า เครื่องมือสำหรับนักพัฒนาที่ต้องประมวลผลโค้ดจำนวนมหาศาล เริ่มขยับลงมาสู่ภาษากลุ่ม Systems Programming มากขึ้น

สิ่งที่น่าสนใจคือ ทีมพัฒนาไม่ได้เลือกเขียนใหม่ทั้งหมด แต่เลือกใช้แนวทาง Mechanical Port หรือการแปลงโค้ดแบบค่อย ๆ ย้ายทีละฟังก์ชันให้มีพฤติกรรมเหมือนเดิมมากที่สุด เหตุผลก็ตรงไปตรงมาครับ Flow เป็นระบบสำคัญที่ใช้ตรวจสอบโค้ดของโปรเจกต์ขนาดใหญ่ เช่น Instagram ดังนั้นการ Rewrite ใหม่ทั้งระบบย่อมมีความเสี่ยงสูงกว่าการรักษาพฤติกรรมเดิมไว้ก่อน แล้วค่อยปรับปรุงภายหลัง

ในการพอร์ต ทีมงานยอมรับใช้ LLM เข้ามาช่วยแปลงโค้ดจาก OCaml เป็น #Rust แบบฟังก์ชันต่อฟังก์ชัน แต่ไม่ได้ปล่อยให้ AI ทำงานลำพัง ทุกการเปลี่ยนแปลงยังต้องผ่านการตรวจสอบจากนักพัฒนา (Human in the loop) และหลายส่วนยังคงเก็บโค้ด OCaml ต้นฉบับไว้ในคอมเมนต์ เพื่อให้สามารถเปรียบเทียบพฤติกรรมระหว่างสองภาษาได้ง่ายขึ้นเมื่อเกิดความแตกต่าง

ความยากที่สุดของโปรเจกต์นี้ไม่ใช่การแปลง Syntax แต่เป็นเรื่องของ Memory Model มากกว่า OCaml มี Garbage Collector คอยจัดการหน่วยความจำให้อัตโนมัติ ขณะที่ #Rust ใช้ระบบ Ownership และ Borrowing ซึ่งบังคับให้ผู้พัฒนาต้องคิดเรื่อง Lifetime ของข้อมูลตั้งแต่แรก เพื่อให้สามารถย้ายโค้ดแบบค่อยเป็นค่อยไป ทีมงานจึงเลือกใช้ `Rc` และ `RefCell` อย่างหนัก เพื่อจำลองพฤติกรรมเดิมของโครงสร้างข้อมูลใน OCaml แม้ว่าวิธีนี้จะช่วยลดความซับซ้อนในการพอร์ต แต่ก็แลกมาด้วยปัญหา Reference Cycle และต้นทุนในการจัดการหน่วยความจำที่สูงขึ้น จนต้นแบบช่วงแรกกลับทำงานช้ากว่าเวอร์ชัน OCaml ในบางกรณีเสียอีก

หลังจากพอร์ตเสร็จ งานจริงเพิ่งเริ่มต้น ทีมพัฒนาค่อย ๆ ไล่ปรับปรุงประสิทธิภาพ ทั้งการลดการจัดสรรหน่วยความจำที่ไม่จำเป็น ปรับ Work-stealing Scheduler และกำจัด Reference Cycle ที่เกิดจากการใช้ Smart Pointer มากเกินไป เมื่อจูนระบบเสร็จ ผลลัพธ์สุดท้ายกลับออกมาน่าประทับใจ โดยหลายส่วนทำงานเร็วขึ้นประมาณ 2 เท่า และในบางขั้นตอนของการวิเคราะห์เชิงลึก ประสิทธิภาพเพิ่มขึ้นอีกราว 30–100% เมื่อเทียบกับเวอร์ชันเดิม

นอกจากเรื่องประสิทธิภาพแล้ว การย้ายมายัง #Rust ยังทำให้ Flow เชื่อมต่อกับ Ecosystem ของ JavaScript รุ่นใหม่ได้ง่ายขึ้น เพราะปัจจุบันเครื่องมือยอดนิยมหลายตัว เช่น Vite, Rolldown และโปรเจกต์ด้าน Tooling อื่น ๆ ต่างก็เลือกพัฒนาด้วย #Rust ทำให้การแชร์โค้ด ไลบรารี หรือองค์ความรู้ระหว่างโปรเจกต์ทำได้สะดวกกว่าเดิม

ปิดท้ายคลิปด้วยเกร็ดที่น่าสนใจ OCaml ซึ่งเป็นภาษาที่ทีม Flow เพิ่งย้ายออกมา คือภาษาที่ Graydon Hoare ใช้สร้าง Bootstrap Compiler ตัวแรกของ #Rust ตั้งแต่ปี 2006 ก่อนที่ Mozilla จะเข้ามาสานต่อ และพัฒนา #Rust จนสามารถคอมไพล์ตัวเองได้ในปี 2011 การที่วันนี้ Flow เดินทางจาก OCaml กลับมาสู่ #Rust จึงเหมือนเป็นอีกหนึ่งวัฏจักรของเทคโนโลยี ที่สะท้อนให้เห็นว่าภาษาใหม่จำนวนไม่น้อย ล้วนเติบโตบนรากฐานของภาษารุ่นก่อนเสมอ 😊 งดงามจริง ๆ
