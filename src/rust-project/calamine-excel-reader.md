# calamine ที่ไม่ใช่ยาแก้แพ้แก้คัน 😅

> 📅 วันที่เผยแพร่: 2026-05-27

มีใครอยากมาเปิดศึกแข่งอ่านไฟล์ Excel ขนาด 1M Rows กันขำ ๆ ไหมครับ กติกาคือเรามีโจทย์โหดระดับหนึ่งเลย เป็นไฟล์ Excel ขนาด 186MB มีทั้งหมด 1,000,001 แถว 41 คอลัมน์ (รวม ๆ ประมาณ 28 ล้านเซลล์) ผู้ท้าชิงที่ร่วมชกในศึกนี้มีทั้ง Go, C#, Python และน้องเล็กสาย System ของเราอย่าง #Rust ที่ส่งตัวแทนชื่อ `calamine` เข้าประกวด ผลลัพธ์ตอนเข้าเส้นชัยบอกเลยว่ากินขาด เพราะ #Rust วิ่งม้วนเดียวจบใช้เวลาแค่ 25 วินาที (ซดข้อมูลเฉลี่ย 1.12 ล้านเซลล์ต่อวินาที) ขณะที่ Go วิ่งตามมาที่ 44 วินาที ส่วนพี่ใหญ่อย่าง C# ล่อไปเกือบ 3 นาที และ Python รั้งท้ายที่ 4 นาทีเศษแบบห่างกันคนละช่วงตัว

แต่เบื้องหลังชัยชนะครั้งนี้ไม่ได้มีดีแค่เรื่องเวลาครับ ความน่าสนใจอยู่ที่ "แท็กติกการคุมทรัพยากร" ของแต่ละภาษา เพราะในขณะที่ Go กลัว RAM ตัวเองจะบวมระเบิดจนโดนระงับสิทธิ์ จึงเลี่ยงไปใช้วิธีคลายซิปแล้วเขียนข้อมูลลงดิสก์ชั่วคราวก่อน (ทำให้ดิสก์โดนเขียนไปถึง 1.5GB) เพื่อลดภาระของ Garbage Collector แต่ฝั่ง #Rust ที่ใช้ `calamine` นั้นลงสนามด้วยกติกาตรงไปตรงมา อ่านไฟล์เข้ามาแค่ 186MB ถ้วน ไม่มีการเขียนดิสก์เพิ่มเลยแม้แต่ไบต์เดียว แถม RAM ที่ใช้ยังขึ้นลงเป็นขั้นบันไดอย่างมีระเบียบตามกลไก Ownership ที่พอตัวแปรไหนหมด Scope ก็เคลียร์ทิ้งทันทีโดยไม่ต้องง้อ GC และไม่มีอาการ CPU กระตุกให้เห็นเลย

หลายคนอาจจะแย้งว่า "เขียน Rust ชนะก็จริง แต่โค้ดปวดหัวตายเลย" จุดนี้แหละครับที่เป็นทีเด็ด เพราะเราเขียนแบบคลีน ๆ ผ่านพลังของ Serde ได้เลย ตัวไลบรารีเปิดให้เราดึงข้อมูลแบบ Lazy ผ่าน Iterator แล้ว Map เข้า Struct ได้โดยตรง แถมถ้าต้องเจอปัญหาโลกแตกอย่างข้อมูลขยะ เช่น คอลัมน์ตัวเลขที่มีค่าพัง ๆ หรือตัวหนังสือปนมา เราก็แค่ประกาศ Type ให้ช่องนั้นเป็น `Option<f64>` แล้วกำกับด้วยฟังก์ชัน `deserialize_as_f64_or_none` ของเค้า เท่านี้ระบบก็กรองขยะทิ้งให้ตั้งแต่ตอน Deserialize โดยที่เราไม่ต้องมาเขียน `if-else` หรือ `try-catch` ซ้อนกันหลายชั้นให้เมื่อยมือ

ความเก๋าอีกเรื่องของ `calamine` คือมันฉลาดพอที่จะเลือกกลยุทธ์ให้เหมาะกับสเปกไฟล์แต่ละประเภท ถ้าเราโยนไฟล์ใหม่อย่าง xlsx หรือ xlsb ให้ มันจะทำการ Lazy loading ดึงเฉพาะข้อมูลแถวที่เราสั่งทันทีโดยไม่โหลดมาเผื่อ แต่ถ้าเป็นตระกูลเก่าอย่าง xls หรือ ods มันก็เข้าใจพฤติกรรมจริงของฟอร์แมตนั้นดีและจะดึงข้อมูลมาทีเดียวทั้งหมด ยิ่งไปกว่านั้น มันยังดึงสูตรคำนวณ (Formula) และโค้ด VBA ของแต่ละชีทออกมาวิเคราะห์ต่อได้ด้วย เรียกว่าตัวเดียวทำได้ครบเครื่องตั้งแต่งานข้อมูลไปจนถึงงานระบบระบบหลังบ้านขององค์กรเลยทีเดียว

ใครที่กำลังปวดหัวกับการทำ Data Pipeline แล้วรู้สึกว่าตัวเก่าที่ใช้มันอืดอาด ลองเปลี่ยนมาหยิบ `calamine` ไปทา เอ้ย!! ไปใช้ไปเทสดูครับ ([https://github.com/tafia/calamine](https://github.com/tafia/calamine)) แล้วในกลุ่มมีใครเคยทำสถิติอ่านไฟล์แบบโหด ๆ ด้วย Rust หรือภาษาอื่นกันได้กี่วินาทีบ้าง แวะมาขิงเอ้ยแชร์เทคนิคกันหน่อยครับ
