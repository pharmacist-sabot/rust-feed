# ยกระดับ Unit Test ด้วย rstest

> 📅 วันที่เผยแพร่: 2026-06-30

หนึ่งในขีดจำกัดที่ท้าทายของการเขียน Unit Test คือการจัดการ Test Dependencies และ Boilerplate Code ที่มักจะบวมขึ้นเรื่อย ๆ แต่ด้วยความสามารถของ Procedural Macro ในภาษา #Rust เราสามารถก้าวข้ามข้อจำกัดนี้ได้อย่างมีประสิทธิภาพผ่านโมเดล Fixture-based Testing ของเครต `rstest` (ณ วันที่เขียนบทความนี้คือ เวอร์ชัน 0.26.1) ที่ใช้มาโครในการทำ Dependency Injection เข้าสู่ฟังก์ชันทดสอบโดยตรงผ่าน Argument เพียงแค่เราประกาศฟังก์ชันด้วย `#[fixture]` เทสตัวอื่น ๆ ก็สามารถดึงค่าผลลัพธ์นั้นไปใช้งานต่อได้ทันที ช่วยให้นักพัฒนาสามารถแยก Logic ของการเตรียมข้อมูลออกจากการทดสอบได้อย่างเป็นระบบ โดยยังคงไว้ซึ่งความปลอดภัยของระบบ Type System ของ #Rust อย่างครบถ้วน

ระบบ Parametrization ของ `rstest` ช่วยอำนวยความสะดวกในการทำ Table-driven Test หรือ Matrix Test โดยใช้คุณลักษณะอย่าง `#[case]` และ `#[values]` เพื่อรันเคสทดสอบที่หลากหลายด้วยฟังก์ชันเดิม แต่จุดที่แสดงถึงการออกแบบเครื่องมือที่ดีคือฟีเจอร์ Magic Conversion ที่เบื้องหลังเป็นการเรียกใช้ประโยชน์จาก `FromStr` trait ทำให้เราสามารถส่ง String Literal ตรง ๆ ในเคสทดสอบ แล้วปล่อยให้คอมไพเลอร์แปลงค่าเข้าสู่ Type เฉพาะทางอย่าง `SocketAddr` หรือโครงสร้างข้อมูลอื่น ๆ ได้โดยอัตโนมัติ ซึ่งสะท้อนให้เห็นว่าระบบ Type และ Trait ของ #Rust ไม่เพียงแต่ช่วยเรื่องความปลอดภัย แต่ยังช่วยให้การออกแบบ API มีความกระชับและเอื้อต่อการใช้งานจริงมากขึ้น

ปัญหาเรื่อง Lifetimes ในการทดสอบมักเป็นเรื่องที่หลีกเลี่ยงยาก โดยเฉพาะเมื่อต้องทดสอบโค้ดที่อิงกับ Local Lifetime หรือโครงสร้างข้อมูลที่มีการอ้างอิงถึงกัน เช่น โครงสร้างข้อมูลที่ใช้ Bump Allocator ซึ่ง `rstest` จัดการเรื่องนี้ผ่านแอตทริบิวต์ `#[by_ref]` ช่วยให้เราสามารถส่ง Reference ของ Fixture เข้าไปในฟังก์ชันทดสอบแทนการย้าย Ownership ได้โดยตรง ทำให้การจัดการ Lifetime ในเทสเคสมีความยืดหยุ่นสูงขึ้นมาก ช่วยลดความจำเป็นในการเขียนโค้ดเลี่ยงบาลี (Workarounds) และรักษารูปแบบสถาปัตยกรรมของโค้ดต้นฉบับไว้ได้อย่างสมบูรณ์

ในแง่ของระบบ Async และการทำงานร่วมกับ I/O ตัว `rstest` นี้ไม่ได้ยึดติดกับ Runtime ใดระบบหนึ่ง ทำให้เราสามารถเลือกใช้ร่วมกับ Tokio หรือ Async-std ได้อย่างอิสระ โดยมีเครื่องมือช่วยลดรูป Boilerplate ของ `impl Future` ด้วยแอตทริบิวต์ `#[future]` ร่วมกับระบบ `#[awt]` (Awaiting) ที่ช่วยลดการเขียน `.await` ซ้ำ ๆ ให้เหลือเพียงการประกาศแอตทริบิวต์แบบ Global นอกจากนี้ยังมีฟีเจอร์ที่ช่วยตอบโจทย์การทำ Data-driven testing เช่น `#[files]` ที่สามารถดึง Path ของไฟล์ผ่าน Glob Pattern มาสร้างเป็นเทสเคสแยกแต่ละไฟล์ได้โดยอัตโนมัติ และระบบควบคุมเวลาอย่าง `#[timeout]` ซึ่งทำงานได้ทั้งระดับฟังก์ชันและระดับเคสรายตัว

ความสามารถในการใช้ `#[once]` เพื่อเตรียมค่าเพียงครั้งเดียวสำหรับทุกเทสเคส ตลอดจนการสืบค้นข้อมูลรันไทม์ผ่าน Context object และการใช้ `#[trace]` เพื่อดัมพ์ค่าตัวแปรเมื่อเทสพัง (Test Failed) ล้วนเป็นการตอกย้ำถึงแนวคิดการเปลี่ยนความซับซ้อนในระดับสถาปัตยกรรมให้กลายเป็นสิ่งที่เรียบง่ายผ่าน Macro System ของ #Rust นั่นเอง
