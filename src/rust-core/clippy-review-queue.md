# วันที่ Clippy เริ่มรีวิว PR ไม่ทัน

> 📅 วันที่เผยแพร่: 2026-07-08

`Clippy` เป็นเครื่องมือที่ชาว #Rust แทบทุกคนเปิดใช้งาน มันเป็นเหมือนด่านแรกที่ช่วยจับโค้ดไม่ค่อยเข้าท่าและแนะนำ Best Practice ต่าง ๆ ให้เรา แต่พอโปรเจกต์ใหญ่ขึ้น คนส่ง Pull Request (PR) ก็เยอะขึ้นตาม จนเกิดปัญหาที่หลายโปรเจกต์ Open Source หนีไม่พ้น นั่นคือ "คนรีวิวไม่พอ"

สาเหตุไม่ได้ซับซ้อนอะไรเลยครับ เพราะทีม Clippy ไม่มีใครได้รับเงินมาทำงานกับโปรเจกต์นี้แบบเต็มเวลา ทุกอย่างอาศัยเวลาว่างของ Maintainer ล้วน ๆ พอ PR ไหลเข้ามาเรื่อย ๆ (ไม่แน่ใจเหมือนกันว่าทีมเปิดรับ PR จาก AI ไหมนะครับ ใครมีข้อมูลอัปเดตได้บอกกันได้เลย) ภาระก็ไปตกอยู่กับคนกลุ่มเดิม ๆ สุดท้ายก็เสี่ยง Burnout กันตามระเบียบ 😢

ทีม Clippy เลยลองเปลี่ยนวิธีคิด แทนที่จะรอ Maintainer ไล่รีวิวทุก PR คนเดียว ก็ชวนให้คนที่ส่ง PR มาช่วยรีวิว PR ของคนอื่นด้วย เกิดเป็น Workflow ใหม่ที่ทำงานร่วมกับ `@rustbot` (ภาพประกอบ) พอเราส่ง PR เข้าไป ระบบ `@rustbot` จะชวนให้ไปดู PR ของคนอื่นก่อน โดยเฉพาะ PR ที่ยังไม่มีใครเข้าไปรีวิว พอเราช่วยรีวิวเสร็จ PR ของเราก็จะถูกจัดให้อยู่ในคิวที่ได้รับความสำคัญจากทีมรีวิวมากขึ้น

หลังจากเราไปรีวิว PR ของคนอื่นเสร็จ ระบบจะใส่ชื่อเราเข้า "ลิสต์คนเท่" (ผมตั้งชื่อเอง 😆) ทำให้ PR ของเราถูกทีม Maintainer หยิบขึ้นมาดูก่อนคิวปกติ ซึ่งไอเดียนี้ได้รับแรงบันดาลใจมาจากระบบ Open Code Review ของ Bevy ที่ให้คนในคอมมูนิตี้มาแลกเปลี่ยนการรีวิวกัน เป็นการแลกเปลี่ยนที่แฟร์ดี ช่วยรีวิวให้คนอื่น วันนี้ พรุ่งนี้ก็มีคนช่วยรีวิวของเรา ผลพลอยได้อีกอย่างคือ คนในคอมมูนิตี้ได้เรียนรู้โค้ดของกันและกันมากขึ้น ความรู้ไม่ได้กระจุกอยู่แค่ Maintainer ไม่กี่คน

นี่ไม่ใช่ครั้งแรกที่ Clippy ปรับตัว จริง ๆ แล้วทีม Clippy เคยแก้ปัญหาแบบนี้มาแล้ว ปีที่แล้วพวกเขาเคยประกาศ Feature Freeze หยุดรับฟีเจอร์ใหม่ชั่วคราว เพื่อเคลียร์งานค้างและจัดระเบียบโปรเจกต์ ผลลัพธ์ออกมาดีจนทีมบอกว่าได้รับทั้งความเชื่อมั่นและความร่วมมือจากคอมมูนิตี้มากขึ้น

รอบนี้ก็เป็นอีกครั้งที่เห็นว่าการดูแลโปรเจกต์ Open Source ไม่ได้มีแค่เรื่องเขียนโค้ด แต่รวมถึงการออกแบบวิธีทำงานให้โปรเจกต์อยู่รอดในระยะยาวด้วย เพราะสุดท้ายแล้ว ต่อให้มี Workflow ดีแค่ไหน ถ้าไม่มีคนดูแลก็ไปต่อยากอยู่ดี
